## Introduction

Building a modern SaaS requires a solid architectural foundation. With the introduction of the Next.js App Router, the paradigm of how we fetch and mutate data has shifted drastically towards **React Server Components (RSC)**.

In this guide, we'll explore how to structure your Next.js application for multi-tenancy.

## The App Router Advantage

By default, components in the App Router are Server Components. This means they are rendered on the server, and only the generated HTML is sent to the client, resulting in zero JavaScript added to the client bundle.

```typescript
// app/dashboard/page.tsx
import { db } from '@/lib/db';

export default async function Dashboard() {
  // Direct database access on the server
  const data = await db.user.findMany();
  
  return (
    <div>
      <h1>Dashboard</h1>
      <ul>
        {data.map(user => (
          <li key={user.id}>{user.name}</li>
        ))}
      </ul>
    </div>
  );
}
```

### Key Benefits

1. **Smaller Client Bundles**: Large dependencies stay on the server.
2. **Direct Backend Access**: Securely query your database without building an intermediate API.
3. **Automatic Caching**: Next.js heavily caches fetches.

## Implementing Multi-Tenancy

To implement multi-tenancy, you usually need a strategy to separate data. The most robust way is to inject a `tenantId` into every database query, ensuring users can only read their respective company's data.

> "A well-architected multi-tenant system is the difference between a side project and an enterprise-grade SaaS."

### Step 1: Middleware Routing

Use Next.js Middleware to parse the subdomain or pathname and inject the correct tenant context.

```typescript
// middleware.ts
import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';

export function middleware(request: NextRequest) {
  const url = request.nextUrl;
  const hostname = request.headers.get('host') || '';

  // Extract subdomain logic...
  const currentHost = hostname.replace(`.yourdomain.com`, '');

  if (currentHost !== 'www') {
    url.pathname = `/${currentHost}${url.pathname}`;
    return NextResponse.rewrite(url);
  }
}
```

## Conclusion

Next.js 14 provides an incredibly powerful toolkit for building fast, secure, and highly scalable SaaS applications. By leveraging Server Components and Edge Middleware, you can create enterprise architectures with minimal overhead.
